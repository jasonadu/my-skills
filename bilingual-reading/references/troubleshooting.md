# 问题排查与可复用经验（双语阅读）

来源：SOP「问题与优化建议」。构建过程中按本表排查，避免重复踩坑。

## 1. 常见问题与解决

| 问题 | 原因 | 解决办法 |
|---|---|---|
| 列表项中文无浅蓝背景 | 最初只给 `p.zh` 写了样式，漏了 `li .zh` | 补 `li .zh` 与 `p.zh` 同规格样式（book_theme.py 已内置） |
| f-string 里 `P('en','zh')` 被当字面文本输出 | f-string 内函数调用未求值 | 必须写成 `{P('en','zh')}`；用 `scripts/fix_braces.py` 批量补花括号 |
| 批量补 `}` 误加到末尾 `page()` 行 | 后处理脚本不分上下文 | fix_braces.py 只处理以 `P(`/`LI(` 开头的行，不碰 `page(`/`img_b64(`；仍出错时手动删除该行尾多余的 `}` |
| `SyntaxError: expressions nested too deeply` | 代码块里的 JSON `{}` 与 f-string 冲突 | 代码块抽成普通字符串变量（`CODE_X = '''...'''`），用 `+ CODE_X` 拼接，不写进 f-string |
| `{<P(` 误写（后处理把 `{` 加在 `<P` 前） | 模板拼接行首是 `<P(...)` | `sed 's/{<P(/{P(/g'` 修正 |
| jpx(JPEG2000) 图浏览器不显示 | PDF 内嵌 JPEG2000 未转码 | PIL 统一转 RGB/JPEG（extract_assets.py 已内置） |
| 图过大导致 HTML 膨胀 | 原图 MB 级 | 宽限 800px、JPEG q≈68，单图压到 30~80KB |

## 2. 可复用经验

1. **先样板后批量**：先做 1 章给用户验收样式，再沉淀共享模板，避免全书返工。
2. **模板与内容分离**：`book_theme.py` 一处改、全局生效；新增章只写正文。
3. **代码块不入 f-string**：含花括号的代码一律抽成独立字符串变量，避免转义地狱。
4. **图先压后嵌**：base64 内嵌前必须压缩，否则单章 HTML 会冲到数 MB。
5. **书签页码与物理页常有偏移**：页范围换算以 PDF 书签（`get_toc()`）为准。

## 3. 后续可选优化方向

- 构建脚本参数化：把「页范围 + 图号映射」做成配置表，减少每章重复代码。
- 加 `build_all.py` 一键顺序构建全部章节。
- 翻译精度：当前为压缩式意译（部分章节把清单类内容合并为要点），
  若需逐句严格对应可再做精修。
- 可加搜索/全文索引（如 Pagefind）支持多章规模的内容检索。
- 若推荐书目按约定跳过，如需补全可另加 `other-books.html`。
